The third calendar build of September (`YY.M.BUILD`, ADR-009): a host can now theme `<excali-editor>` with its own palette. A `theme` attribute makes the theme the host's, and `--excali-canvas-background` paints the canvas in the host's colour. v26.9.2 stays as published.

**Assets**

- `excali-web_26.9.3.tar.gz`: the web runtime as `scripts/web/build.sh` builds it: `excali_editor.js` (the ES module that defines `<excali-editor>`), `excali_editor_bg.wasm`, `excali.css` and `fonts/` (the range-split font files, their licences and `manifest.json`). Built, packed reproducibly and uploaded by `.github/workflows/release.yml` from this tag.
- `Excali.Example_26.9.3_aarch64.dmg`: the example app (`examples/tauri-app`) for Apple silicon, signed with a Developer ID, notarized by Apple and stapled, built by `scripts/release/macos-dmg.sh 26.9.3 --upload v26.9.3`.
- `Excali.Example_26.9.3_aarch64.app.tar.gz` and `Excali.Example_26.9.3_aarch64.app.tar.gz.sig`: the app bundle the in-app updater downloads, and its minisign signature, checked against the public key in `tauri.conf.json` before it installs.
- `latest.json`: the updater's endpoint document (version, date, and the `darwin-aarch64` signature and URL). The app reads it from https://github.com/HutsonLabs/excali-rust/releases/latest/download/latest.json, so installed v26.9.2 apps offer to move to this release.
- `SHA256SUMS`: a `shasum` line for each of the above.

Fetch and check the web runtime, then unpack it into a directory, with `scripts/release/fetch.sh 26.9.3 vendor/excali` (curl, tar and shasum or sha256sum), or by hand: `gh release download v26.9.3 -R HutsonLabs/excali-rust -p 'excali-web_*' -p SHA256SUMS && shasum -a 256 -c SHA256SUMS --ignore-missing`. Tauri hosts take the plugin as `tauri-plugin-excali = { git = "https://github.com/HutsonLabs/excali-rust", tag = "v26.9.3" }`.

**What changed since v26.9.2**

- Host theming for `<excali-editor>` (ex-807, https://github.com/HutsonLabs/excali-rust/pull/164):
  - While the element has a `theme` attribute, the theme is the host's. The toggle is off, as upstream leaves it for a `theme` prop without `onThemeChange` (`index.tsx:142-147`): there is no main-menu theme item, help-dialog row or command-palette command, and Alt+Shift+D does nothing. Removing the attribute gives the toggle back.
  - `--excali-canvas-background`, set on the element or inherited, paints the on-screen canvas unfiltered in both themes behind a scene on the default white background. Outline arrowheads are filled with it too. A scene with its own background keeps it, and exports (PNG, SVG, clipboard PNG) never use the host colour.
  - The integration guide has a new Theming section: the tokens and their specificity, the `theme` attribute, `--excali-canvas-background`, `--color-selection` and repainting after a palette switch. The term.hut API contract matches it.

The integration guide (https://hutsonlabs.github.io/excali-rust/architecture/integration/) walks a host through the web runtime and the Tauri plugin; the transcript of the walk in a fresh clone is https://hutsonlabs.github.io/excali-rust/architecture/integration-walk/.

Not published to crates.io, npm or any other registry: the crates keep `publish = false` (the crates.io task is deferred by the owner).
