The second calendar build of September (`YY.M.BUILD`, ADR-009): the example Tauri app now ships as a signed and notarized macOS disk image that updates itself in place, and the editor gains the work merged since v26.9.1. v26.9.1 stays as published.

**Assets**

- `excali-web_26.9.2.tar.gz`: the web runtime as `scripts/web/build.sh` builds it: `excali_editor.js` (the ES module that defines `<excali-editor>`), `excali_editor_bg.wasm`, `excali.css` and `fonts/` (the range-split font files, their licences and `manifest.json`). Built, packed reproducibly and uploaded by `.github/workflows/release.yml` from this tag.
- `Excali.Example_26.9.2_aarch64.dmg`: the example app (`examples/tauri-app`) for Apple silicon, signed with a Developer ID, notarized by Apple and stapled, built by `scripts/release/macos-dmg.sh 26.9.2 --upload v26.9.2`.
- `Excali.Example_26.9.2_aarch64.app.tar.gz` and `Excali.Example_26.9.2_aarch64.app.tar.gz.sig`: the app bundle the in-app updater downloads, and its minisign signature, checked against the public key in `tauri.conf.json` before it installs.
- `latest.json`: the updater's endpoint document (version, date, and the `darwin-aarch64` signature and URL). The app reads it from https://github.com/HutsonLabs/excali-rust/releases/latest/download/latest.json, so whichever release is marked Latest is the one installed apps move to.
- `SHA256SUMS`: a `shasum` line for each of the above.

Fetch and check the web runtime, then unpack it into a directory, with `scripts/release/fetch.sh 26.9.2 vendor/excali` (curl, tar and shasum or sha256sum), or by hand: `gh release download v26.9.2 -R HutsonLabs/excali-rust -p 'excali-web_*' -p SHA256SUMS && shasum -a 256 -c SHA256SUMS --ignore-missing`. Tauri hosts take the plugin as `tauri-plugin-excali = { git = "https://github.com/HutsonLabs/excali-rust", tag = "v26.9.2" }`.

**What changed since v26.9.1**

- The example app's in-place updater and the signed, notarized release script (ex-805, https://github.com/HutsonLabs/excali-rust/pull/162): a release build checks `latest.json` in the background, never blocking the editor and never in dev or smoke runs, and offers Install and restart / Later; the update is verified with minisign before it installs. The app's own commands are allowed in the main window only. `scripts/release/macos-dmg.sh` builds with the signing identity given at build time (none in `tauri.conf.json`, no entitlements), notarizes, staples and stages the DMG, the updater tarball and signature, `latest.json` and `SHA256SUMS`.
- The styles panel's controls and picks in `<excali-editor>` (ex-540, https://github.com/HutsonLabs/excali-rust/pull/155).
- M5, the editor usable in a desktop layout: the footer above the canvas, the styles panel gap, the dark theme and the grid fixed (ex-m5, https://github.com/HutsonLabs/excali-rust/pull/158).
- Copy as PNG, open (Ctrl+O) and save as (Ctrl+Shift+S) (ex-542, https://github.com/HutsonLabs/excali-rust/pull/159).
- Shortcut actions that now perform: deselect, flip, lock, copy and paste styles, view mode and theme (ex-541, https://github.com/HutsonLabs/excali-rust/pull/160).
- The hyperlink editor, Ctrl/Cmd+K, with upstream's DOM and stylesheet (ex-543, https://github.com/HutsonLabs/excali-rust/pull/161).

The integration guide (https://hutsonlabs.github.io/excali-rust/architecture/integration/) walks a host through the web runtime and the Tauri plugin; the transcript of the walk in a fresh clone is https://hutsonlabs.github.io/excali-rust/architecture/integration-walk/.

Not published to crates.io, npm or any other registry: the crates keep `publish = false` (the crates.io task is deferred by the owner).
