## 2026-09-29 · ex-705 · Lasso selection

The lasso tool now selects the way upstream's does. A freehand path selects what it encloses: in the default `contain` mode, only elements whose outline and label lie wholly inside or on the path, with the path crossing neither, and a group only when every member is inside. In `overlap` mode it also selects anything the path crosses. Only the visible part of an element clipped by its frame counts. Locked elements and bound text are never selected. A selected frame stands for its children, groups are selected whole, and a lone line or arrow gets its linear element editor. Shift adds to the current selection. Pressing on the selection, one of its handles or the common box of several selected elements drags or transforms them, as the selection tool does; Ctrl/Cmd+Alt lassos even there. The port is `crates/excali-editor/src/lasso.rs` (`getLassoSelectedElementIds`, `LassoTrail`), wired into the web editor's lasso tool (`Gesture::Lasso` in `crates/excali-wasm/src/editor.rs`). Upstream draws the lasso trail as an animated SVG path; that drawing is not part of this change, just as the eraser's trail is not drawn yet. PR: [#135](https://github.com/HutsonLabs/excali-rust/pull/135).

## 2026-09-29 · ex-704 · Bucket fill tool

The bucket fill tool now fills a closed region the way upstream does. `crates/excali-editor/src/bucket_fill.rs` ports `packages/element/src/bucketFill.ts`. It finds the owner (the topmost closed, visible element under the click) and gathers the visible outlines around it; outlines hidden under opaque paint are clipped away. From those outlines it builds a planar arrangement: nodes merged within 0.5 px, segments split at intersections and T-junctions, and gaps of up to 6 px bridged. It then walks the faces and keeps the smallest bounded face that contains the click. Islands inside that face are cut out as keyhole holes, and the ring is simplified. Regions formed only by open lines are found by an owner-less search box that doubles in size up to three times. The fill goes above the topmost opaque element that overlaps the region, or else below the lowest element that has to stay visible. `bucket_fill_click` ports `App.bucketFill.ts`'s `fill`. It decides whether a click restyles existing paint (a re-click, or an orphaned fill), shows a toast (`noRegion`, `tooComplex`), does nothing (empty canvas), or inserts a new strokeless line polygon. The new polygon takes the owner's frame and groups and uses the fallback green when the background is transparent. Supporting additions: `excali_core::color::is_opaque_color` (`isOpaqueColor`) and `excali_scene::freedraw::get_freedraw_stroke_center_points` (`getFreedrawStrokeCenterPoints`). PR: [#132](https://github.com/HutsonLabs/excali-rust/pull/132).

## 2026-09-29 · ex-533 · excali-math js::sin/cos match V8 bit for bit; exact comparisons in the editor tests

The editor's gesture tests now compare every number exactly. Rotating, resizing, binding and editing lines are checked against upstream's recorded output with `==` (`-0` equal to `0`) instead of within a millionth of a millionth, and all 410 transform cases, the binding cases and the linear-element cases pass. This was possible because `excali_math::js` already computes `Math.sin` and `Math.cos` as Node 26 does: V8's own fdlibm with the fused multiply-adds clang emits on arm64 (ex-009, [ADR-011](@/decisions/adr-011-platform-independent-float-maths.md)), not the glibc-derived routines this task assumed. 20,001 sampled arguments give Node 26.10.0's exact doubles.
