## Tauri hosts the same module

Tauri renders the frontend in the platform webview and lets "developers integrate any front-end framework that compiles to HTML, JS and CSS" (Tauri README, read 2026-09-28). The `<excali-editor>` module is plain ES + WASM, so a Tauri app includes it the way term.hut does: copy the release directory into the frontend dist and import it. `withGlobalTauri` is optional; the editor does not call Tauri APIs itself.

Versions on crates.io on 2026-09-28: `tauri` 2.12.0, `tauri-build` 2.7.0, `wry` 0.57.0, `tao` 0.37.1, `tauri-plugin-fs` 2.6.0, `tauri-plugin-dialog` 2.8.0 (see [evidence](../../evidence/)).

## `tauri-plugin-excali`

A thin plugin for hosts that do not already have file commands like term.hut does (`crates/tauri-plugin-excali`, built against `tauri` 2.12.0 and `tauri-plugin-dialog` 2.8.0). Each command runs the code `excali` runs ([command line](../cli/)), so the plugin and the CLI answer the same for the same file. The webview calls them as `plugin:excali|<command>`; arguments are camelCase, a cancelled dialog resolves to `null`, and an error rejects with its message.

| Command | Arguments | Does |
|---|---|---|
| `open` | `kind?`: `"scene"` (default) or `"library"` | Open dialog with upstream's filter, "Excalidraw files" (`excalidraw`, `json`, `png`, `svg`, `data/json.ts:106-112`) or "Excalidraw library files" (`excalidrawlib`, `json`, `LibraryMenuHeaderContent.tsx:161-167`); resolves to `{ path, name, text }`, the text being the JSON `load` and `importLibrary` take (a `.png` or `.svg` file's embedded scene decoded by `excali-core`) |
| `save` | `text`, `kind?`, `path?`, `name?` | Writes the text to `path`, or where a save dialog says ("Excalidraw file", `<name>.excalidraw`, or "Excalidraw library file", `library.excalidrawlib`, `data/json.ts:93-98, 147-160`); resolves to the path |
| `export` | `scene`, `format` (`"png"` or `"svg"`), `options?`, `save?: { path?, name? }` | Headless export, `excali render` / `excali export` (no webview needed): the PNG bytes (an `ArrayBuffer`) or the SVG text; with `save`, writes the file (the dialog suggests `<name>.png`, or `.excalidraw.png` when the scene is embedded, as `exportCanvas` does, `data/index.ts:139-150, 187-193`) and resolves to the path. `options`: `scale`, `padding`, `background`, `darkMode`, `embedScene`, `frame`, `skipInliningFonts` |
| `library_fetch` | `url` | Fetches a library URL after the allow-list check (upstream's `validateLibraryUrl`, `data/library.ts:497-528`, `ALLOWED_LIBRARY_URLS` by default); the JS side calls it from the `library-fetch` event |
| `validate` | `text`, `name?` | Parses and restores the text, read as a file called `name` (`scene.excalidraw` by default), and resolves to `excali validate --json`'s report |

Registering it (the app registers `tauri-plugin-dialog` too; the plugin opens its dialogs from Rust):

```rust
tauri::Builder::default()
    .plugin(tauri_plugin_dialog::init())
    .plugin(tauri_plugin_excali::init())
```

`tauri_plugin_excali::Builder` sets the library allow-list (`library_urls`), the font directory exports read (`fonts_dir`: an app bundles `crates/excali-text/assets/fonts` as a resource and points here), the `source` exports write, and other dialogs or transports. Answering the editor's `library-fetch` event:

```js
const { invoke } = window.__TAURI__.core;
editor.addEventListener("library-fetch", (e) => {
  e.preventDefault();
  e.detail.respond(invoke("plugin:excali|library_fetch", { url: e.detail.url }));
});
```

Capability file shipped with the plugin (`crates/tauri-plugin-excali/capabilities/excali.json`, in the style of term.hut's `capabilities/default.json`), copied into the app's `capabilities/`:

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "excali",
  "description": "The excali plugin's commands in the window that embeds <excali-editor>",
  "windows": ["main"],
  "permissions": ["excali:default"]
}
```

`excali:default` allows the five commands; `excali:allow-<command>` and `excali:deny-<command>` (`permissions/autogenerated`, generated by `tauri-plugin`'s build script) narrow it. The webview needs no `dialog:` permission, because the dialogs are opened on the Rust side.

What the plugin does not trust the webview with:

- `save` and `export` write only a path that one of the plugin's own dialogs returned (an `open` grants its file, so Save after Open writes back without a dialog); any other path is refused.
- `library_fetch` checks the URL against the allow-list again on the native side, fetches only `https`, holds every redirect to the same list (a browser's `fetch` would follow any), and refuses a body over 64 MiB.

The tests (`crates/tauri-plugin-excali/tests`) run every command through Tauri's IPC and ACL on the mock runtime, with the ACL built from the shipped permission files and this capability, scripted dialogs and a scripted network.

CSP: the module needs `'wasm-unsafe-eval'` in `script-src`. In the example app on macOS (WKWebView), removing it makes `init()` reject with "Refused to create a WebAssembly object because 'unsafe-eval' or 'wasm-unsafe-eval' is not an allowed source of script" (smoke run, 2026-09-29); with it, the editor mounts, opens, saves and exports with no violation reported. The [integration guide](../integration/) gives the policy per platform and for a plain browser page.

## Example app

`examples/tauri-app` (task `ex-606`) is a complete host: `ui/` is plain HTML and ES modules (a toolbar and `<excali-editor>`), the web runtime is copied into `ui/excali/` by `beforeDevCommand` and `beforeBuildCommand`, `src-tauri/` registers `tauri-plugin-dialog` and, at setup, `tauri-plugin-excali` with `fonts_dir` pointed at the bundle's `fonts/` resource, and ships `capabilities/excali.json` unchanged. Its CSP:

```json
"csp": {
  "default-src": "'self'",
  "script-src": "'self' 'wasm-unsafe-eval'",
  "style-src": "'self' 'unsafe-inline'",
  "img-src": "'self' data: blob:",
  "font-src": "'self' data:",
  "connect-src": "'self' ipc: http://ipc.localhost"
}
```

`cargo tauri dev` in `examples/tauri-app/src-tauri` opens the window; `cargo tauri build --bundles dmg` builds the (unsigned) macOS image. Its tests run the app's own context on the mock runtime (`tests/app.rs`), and `scripts/smoke.sh` runs the built app in the platform webview, where `ui/app.js` opens, saves, saves as and exports through the plugin and reports; CI runs both on macOS (`tauri-example`). See the example's `README.md`.

## Native headless use

`excali-cli` and the plugin share `excali-raster`, so a Tauri backend can render thumbnails or previews of `.excalidraw` files without a webview, for example for a file tree, exactly as term.hut's `preview.js` could use a server-side thumbnail over SSH.
